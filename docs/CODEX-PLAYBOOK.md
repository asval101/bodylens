# Codex 迭代手册（CODEX-PLAYBOOK）

PRD 第 8 节把比赛交付拆成两类：产品闭环 + 开发记录可复现性。本文件把“接下来做什么”拆成 6 轮可独立验收的迭代，每轮配一条可直接粘贴给 Codex 的指令。

## 使用规则

1. **一轮 = 一个可验收的改动**。不要把两轮合成一次对话，否则 diff 无法评审，也拿不到清晰的 Prompt 链。
2. 每轮开始前先把 `AGENTS.md`、`PRD.md` 相关小节、`docs/UI-SPEC.md` 一起喂给 Codex（或确认它能自动读取）。
3. 每轮结束按「固定收尾」执行，**先测试再提交**。
4. 每轮对话记录存到 `docs/prompt-log/R{n}/`（截图或导出），这是比赛 25% 那一项的直接材料。

## 固定收尾（每轮必做）

```bash
npm test                 # 必须全绿
npm start                # 手动走一遍本轮涉及流程
# 浏览器检查 1366 / 1024 / 390 三档宽度
```

然后拆成 3–5 个 commit 提交，粒度示例见 `AGENTS.md` 第 7 节。截图存 `docs/evidence/R{n}/`。

## R1 数据与影响类型补全

**为什么先做**：`data/catalog.js` 现有 `harm` 27 条、`benefit` 17 条，**没有 `mixed`**。而 PRD 5.5 要求至少四类（有益 / 不利 / 多重条件 / 未收录），AC-13、AC-14 直接依赖它。这是数据契约层的缺口，不补则后面的规则都建在沙子上。

**触及**：`data/catalog.js`、`domain.js`、`styles.css`、`tests/domain.test.cjs`

**给 Codex 的指令**

```
读 AGENTS.md 第 5 节的内容红线和 PRD 5.5 节。

任务：为影响类型补齐四态契约，但不要新增任何健康结论内容。

1. 在 domain.js 中定义影响类型常量：harm / benefit / mixed / unmapped，
   并提供 normalizeEffectType(type) 与 isSupportedType(type)。
2. mixed 表示"同一行为对该器官同时存在有益与不利影响，或仅在特定条件下成立"。
   不要为了用上 mixed 而修改现有 44 条 effect 的类型判定——现有条目保持原类型。
3. unmapped 是渲染层状态，不是数据字段：当某行为对某器官没有条目时，
   详情区必须显示"当前未收录对应结论"，并附一句说明"未收录不代表无害"。
   不要把它写成"暂无数据"。
4. styles.css 新增 .marker-mixed（铜+薄荷双色描边）与 .marker-unmapped（--faint 中性），
   并在图例区加入这两种标记的文字说明。
5. tests：新增 4 条用例——
   - 未知类型归一化为 unmapped 而非抛错
   - 四种类型都能取到图例文字
   - effect 的 source 不存在于 sources 时校验失败
   - 同一行为同一器官出现多条 effect 时按类型分组而非合并

约束：不得修改 PRD、不得新增外部请求、不得改变现有 44 条 effect 的 type 值。
先给我看 domain.js 的类型定义和测试清单，我确认后再动 styles.css。
```

**验收**：AC-13、AC-14；`npm test` 从 6 条涨到 10 条以上。

## R2 人体结构与器官交互

**为什么单独一轮**：PRD 明确要求“器官按真实相对位置紧密排列”“悬停不挤动相邻器官”“每个器官有等效文字按钮”。这是 AC-09/10/11/12 的集中区，也是最容易被做成“点不中、会跳位”的地方。

**触及**：`anatomy.js`（通过 `scripts/prepare-anatomy.py`）、`app.js`、`styles.css`、`index.html`

**给 Codex 的指令**

```
读 PRD 5.4 与 docs/UI-SPEC.md 第 5 节。

任务：让人体器官的交互在三种宽度下都准确、稳定、可键盘操作。

1. 先输出一份现状核对表：data/catalog.js 中 10 个器官的 anchor 坐标，
   与 anatomy.js 中对应路径的实际包围盒中心是否一致。不一致的列出来，不要直接改。
2. 悬停与点击的命中区必须与视觉路径一致，且缩放后（沉浸视图 635px / 窄屏 540px）
   仍要一致。当前若存在几何缩放导致的偏移，用 getBoundingClientRect 归一化坐标修复。
3. 悬停只允许改 opacity 与 transform: scale(1.03)，transform-origin 取器官自身中心。
   禁止改变 margin、width、position 等会引起重排的属性——这是"挤动相邻器官"的根因。
4. 键盘可达：每个器官在 DOM 中有一个等效的文字按钮，Tab 可达、Enter 激活、
   focus-visible 显示 --mint 描边。器官 SVG 内的可点区域也加 role="button" 与 tabindex。
5. 系统分层与正背视图必须是真实对应的图层，不允许只换按钮文字而显示同一张图。
   如果当前存在这种复用，明确指出在哪个器官上。

约束：先只输出核对表和第 3 点的修复方案，不要一次性重写 app.js。
```

**验收**：AC-09、AC-10、AC-11、AC-12。

## R3 综合模式与共同关联

**触及**：`domain.js`、`app.js`

**给 Codex 的指令**

```
读 PRD 5.5 与 6.3 节。

任务：让综合模式在"多条行为共享同一器官"时的呈现不产生任何合并或抵消。

1. 对同一器官，按来源行为分组列出结论，每组保留自己的来源与适用范围。
2. 禁止出现：净健康分、抵消结论、"运动抵消吸烟"式表述、任何聚合求和。
3. 新增"共同关联器官"视图：只列出被 ≥2 条已选行为同时命中的器官，
   每个器官下标注命中它的行为名称，点击可跳转到该器官详情。
4. 单项模式与综合模式切换时的行为保留规则按 PRD 2.2：
   单项只保留一项，综合允许追加，各自情境互不覆盖。
5. tests：新增用例——
   - 两行为命中同一器官时输出 2 组而非 1 组
   - 一行为 harm、一行为 benefit 时不产生净结果
   - 共同关联器官的计算只统计命中数 ≥2 的
   - 移除一条行为后，已加入今日计划的任务不被删除（PRD 6.3）

约束：不新增资料内容。所有结论必须来自 catalog 中已有条目。
```

**验收**：AC-13，以及 PRD 6.3 的三条特殊规则。

## R4 本地数据、备份与跨日

**为什么重要**：这是 PRD 里规则最密的一节（7.4 共 9 条），也是 AC-20~AC-23 的集中区。且 PRD 建议的第三条 AI 对话链正好是这个主题。

**给 Codex 的指令**

```
读 PRD 第 7 节全文，共 9 条恢复规则，逐条对应实现。

任务：让备份恢复在异常输入下不损坏现有数据。

1. 导出：文件名 bodylens-backup-YYYY-MM-DD.json，含 schemaVersion、应用版本、
   资料版本、导出时间、时区、基本信息、工作区选择、全部计划与偏好。导出前提示文件含明文生活记录。
2. 导入校验顺序固定为：文件类型 → 可解析性 → schemaVersion 兼容性 → 必填字段 →
   字段数据类型 → 大小上限 5MB。任一步失败即拒绝，**原数据一字不动**。
3. 恢复流程：先展示摘要（导出时间、基本信息、计划数量、兼容性问题、将替换的范围），
   用户确认后才替换。替换前存一个本地恢复点，成功后提供"撤销恢复"。
4. 未知行为 ID 的计划保留为普通任务并标记"原资料暂不可用"；未知行为不进入分析引擎。
5. 日期：计划以本地日期字符串归档。跨午夜间检查不得误判旧任务为今天。
   导入时不做 UTC 转换导致跨日。
6. 备份中的文本一律按纯文本渲染，不解析 HTML、不执行脚本。
7. localStorage 写入失败/配额不足必须抛出可见提示，禁止"未写入却提示已保存"。
8. tests 至少 8 条：损坏 JSON、不兼容版本、超 5MB、缺必填字段、未知行为 ID、
   跨日计划、脚本注入文本、写入失败回滚。

约束：不改动 data/catalog.js。恢复点的存储位置和容量上限先告诉我，再实现。
```

**验收**：AC-20 ~ AC-23。

## R5 响应式、无障碍与离线审计

**给 Codex 的指令**

```
读 PRD 第 10 节 AC-24 / AC-26 / AC-27。

任务：做一次纯审计，先出问题清单，不要直接改代码。

1. 在 1366×768、1024×768、390 三档宽度下，列出出现横向滚动、
   文字裁切、控件被遮挡的具体元素与选择器。
2. 检查页面所有可交互元素的键盘可达性，列出缺失 focus 样式或无法 Tab 到达的。
3. 检查对比度：--text / --muted / --faint 在 --bg 与 --panel 上的实际对比度，
   低于 4.5:1 的组合列出来（--faint 预计不达标，说明它当前用在哪些关键信息上）。
4. 检查所有外部请求（字体、图像、CDN），任何一条都必须移除或本地化。
5. 检查 prefers-reduced-motion 生效后，悬停、点击、分析、切视图是否仍可完整使用。

输出格式：问题清单表格（文件 / 选择器 / 问题 / 影响哪条 AC / 建议改法），
按严重程度排序。我确认优先级后你再动手。
```

## R6 人体素材精修（持续，风险最高）

**必须先承认的现实**：PRD 的目标是“接近医学解剖插画”，而当前是 SVG 图稿细化。用一个多月达到专业医学插画水平在人力上不现实。**建议把目标明确改为“结构准确、层次清晰、有体积感的风格化解剖”**，并在技术文档里论证这个取舍——评委扣的是“说了没做到”，不是“目标定得务实”。

**给 Codex 的指令**

```
读 PRD 5.4 全部要求。

任务：在不追求照片级写实的前提下，解决"看不清结构"这个真实问题。

1. 检查并修正器官相对位置：心脏位于双肺之间偏人体左侧（屏幕右侧）、
   肝脏在人体右上腹（屏幕左侧）、胃在人体左上腹（屏幕右侧）。
   注意"人体左右"与"屏幕左右"相反，标注与命中区必须一致。
2. 肺：体现双肺与分叶轮廓，不要画成两团对称椭圆。
3. 肠道：腹腔内自然盘曲，不要排成整齐的回形。
4. 用三种手段增强体积感，优先级从高到低：
   ① 单侧光源的明暗（一组 radial-gradient 即可，不要多层叠加）
   ② 器官之间的遮挡关系与阴影分离
   ③ 表面纹理（已有 textures 素材，仅用于肺与肠道）
5. 深层器官被遮挡时通过系统分层与局部放大查看，不要把全部器官平铺到同一层。
6. 禁止：统一荧光化、血腥切口、病理化渲染。

约束：先给方案，说明每个器官打算改什么，我确认后再改 anatomy.js。
不引入新的外部素材，除非能明确许可（记录到 assets/asset-licenses.json）。
```
