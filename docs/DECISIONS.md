# 开发决策记录

本文件记录影响方向的决定，最新的在最上面。每次决定单独提交一次，便于还原演进过程。

## 2026-10-20｜两项冲突已裁决

### 一、身体年龄：暂定保留（复议中，未定稿）

**决定**：保留「身体年龄」作为首屏总量指标，并修改 `AGENTS.md` 第 5 节第 3 条的原禁令。

**约束**（四条同时成立才允许展示）：

1. 标注「估算值，非体检结果」
2. 取整到年，不显示小数（写「约 4 岁」，不写「4.1 岁」）
3. 附证据等级与出处
4. 不得据此换算「还能活多久」或任何形式的寿命预测

**理由**：身体年龄是普通人唯一能立即理解的总量指标；「负荷 61/100」缺乏体感。保留它同时守住边界——身体年龄是状态描述、有区间、可比较；寿命预测是结果断言，既敏感又不可验证，两者不是一回事。

**已否决**：改用纯负荷分值的方案（安全但失去唯一有力的总量表达）。

**后续（2026-10-20 记录）**：本条为暂定结论，约定次日复议。作者希望再试「分钟制」作为主要表达——分钟制属于展示层选择，与本条四条约束不冲突，可在界面层并行试验，对比实际效果后再定稿。

### 二、技术栈：不动，继续原生

**决定**：前端保持原生 HTML/CSS/JS、零运行时依赖，不引入 React/Next/任何构建链。AI 解读作为**可选增强**，由服务端一个极小代理脚本调用大模型接口实现。

**做法**：

- Key 不进入浏览器，前端不直连任何 API
- 无网络或无密钥时，解读降级为本地规则文案，产品功能完整可用
- AC-24（断网可用）、AC-28（10 分钟启动）两项硬指标不受影响

**理由**：换框架会让上述两条硬指标同时作废，而它们正是「过程可复现」25 分的抓手；现有 46 个文件重写属于纯损耗。AI 作为增值项而非必需品，同时解决了「演示时没有历史数据、AI 显得多余」的问题。

**已否决**：Next.js + Vercel 重写方案。

## 2026-10-19｜V2 推倒重做

**决定**：不再在现有 V2 结构上继续打补丁，重新组织界面与信息架构。旧版本代码保留在历史里，不删除。

**原因**：V2 在短时间内连续叠加了分层景深、器官聚焦、三套界面方案等改动，界面元素和信息密度失控——单屏同时出现记录、负荷、身体年龄、恢复轴等多个模块，用户无法判断该先看什么。

**做法**：

- 保留本仓库和全部提交历史，不新建仓库。理由：比赛评审「过程可复现与演进链路」占 25%，历史本身是交付物。
- 新版本在本仓库继续提交，旧代码不回滚、不删除。
- 新版本以「信息密度」为第一验收项：先定首屏焦点，再补功能。

**待裁决**（尚未决定，不在本次提交范围内）：

1. `AGENTS.md` 第 5 节禁止输出器官年龄、损伤百分比、统一健康分、寿命预测；新方案涉及「身体年龄」。二者冲突，需先决定是改红线还是改方案。
2. `AGENTS.md` 锁定原生 HTML/CSS/JS、零运行时依赖、禁止 CDN；若引入在线 AI 解读，需要重新设计离线降级方案。
