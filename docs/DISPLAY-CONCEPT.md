# 显示方式：牵连与留存

> 验证原型：`design-lab/echo.html`（独立单文件，零依赖，不读写 localStorage）
> 状态：方向验证，未接入 `app.js`

## 1. 要解决的问题

用户反馈现有界面「不够直观」，希望让用户真正意识到行为对身体的后果，并在做有害行为时产生阻力。

常见解法是把后果换算成数字：风险倍数、健康评分、寿命分钟。这条路有三个绕不过去的坎：

- **数字会诱导Linear外推。** 每天 1 支烟的风险已达每天 20 支的约 46%，按支数线性折算只会算出 5%，差 9 倍。
- **数字必须落到"人群平均"上。** 一旦用户拿「我认识的人抽了一辈子也没事」来反驳，整个产品的可信度就没了。
- **数字暗示可加减。** 「少活 20 分钟」天然让人以为可以靠运动赚回来，而 WHO 的证据并不支持这种抵消。

而项目已有的 `data/catalog.js` 本身就写明了「现有资料不支持按每坐一小时计算损伤」。也就是说，数据层面早已拒绝了量化表达，只是界面还没跟上。

## 2. 核心命题

**不给分数，给留痕。**

不问「这件事有多坏」，只回答两个问题：

1. **牵动了哪几处**（空间）
2. **会留多久**（时间）

这个转换带来三个结果：

- 不需要个体概率，因此不触碰 PRD 的内容红线
- 不需要线性外推，因此不会被剂量曲线证伪
- 天然区分「现在停还来得及」和「停不下来」，因此指向行动

## 3. 三个维度

| 维度 | 编码方式 | 读法 |
|---|---|---|
| 方向 | 颜色：暖红 = 不利，暖绿 = 有益，琥珀 = 同一处被拉向两边 | 这是好事还是坏事 |
| 强度 | 轮廓亮度与填充浓度 | 影响有多大 |
| 留存 | 外围虚线环的粗细 | 停手之后多久才散 |

「被拉向两边」这一档对应 PRD 5.5 要求的第四种影响状态（多重/条件相关），当前 `catalog.js` 尚缺 `mixed` 类型，原型已在视觉层预留。

## 4. 六档回落刻度

所有影响都用同一把尺子衡量——**停手之后多久消失**：

```
数小时 · 数天 · 数周 · 数月 · 数年 · 不完全回落
```

这把尺子的价值在于统一。它让"喝水"和"抽烟"可以放在同一张桌子上比较：

- 喝水：肾脏受益**数小时**，所以每天都要喝，攒不成资本
- 刷牙：口腔受益**数小时**，所以才需要一天两次
- 抽烟：肺**数月**、心**数年**、肾**不完全回落**

用户不需要理解流行病学，就能自己得出结论。这比任何说教都有效。

**「有益行为也会回落」是这个框架里最重要的诚实。** 它阻止用户把健康行为当成存款，也顺带解释了为什么习惯需要每天重复。

## 5. 两种视角

顶部切换「此刻 / 如果一直这样」：

- **此刻**：所有影响都显示，包括那些几小时就散去的
- **如果一直这样**：短期影响整体退场，只留下会沉淀的部分

切换时画面会真的变——眼睛、脊柱、肠道暗下去，肺、心、口腔、肾留着。这个"褪去"的动作本身就是论证：**你现在担心的那些，大部分会自己消失；留下来的那几个，才是需要处理的。**

前后两个视角的数字也会同步变化（8 处 → 5 处），让"哪些是暂时的"变成可以数出来的事实。

## 6. 视觉语言

- 人体是**线稿**，不追求解剖精度：结构可辨即可，明确不冒充医学插画
- **颜色只出现在被影响的地方**：未受影响的身体近乎无色，画面里的每一处暖色都是信息
- 受影响器官带缓慢呼吸（6.4s，各器官错相），表达"这是活的、正在变化的"
- 标签仅在器官被点亮时出现，未选择时画面保持干净的人体
- 两侧竖排铭文补足图谱气质，不承载信息

## 7. 文案原则

右栏每一条影响由三句话组成，全是日常语言：

1. **此刻**：现象，不说机制名词（「烟刚到肺泡，纤毛被麻痹，暂时扫不动灰尘」）
2. **长期**：后果，附证据强度提示（「长期暴露与肺癌、慢阻肺相关，是证据最扎实的一项」）
3. **回落**：停手后的实际走向，包括不可逆的部分（「牙龈炎症数月内改善，已吸收的牙槽骨不会回来」）

第 3 句是整套设计的关键。多数健康应用只讲危害，不讲撤销条件；而人真正需要的是撤销条件。

## 8. 实现约束

- 单文件、零依赖、离线可用，符合 AC-24
- 不引用 `app.js` / `domain.js` / `vfx.js`，不写 localStorage
- 动效遵循 `prefers-reduced-motion`
- 同一器官的多个行为取最大值而非相加——相加就是被我们批评的线性外推
- 强度低于 0.05 的器官不点亮，因为"几乎没有影响"本身需要被看见

## 9. 接入真实数据前要补的字段

原型用的是 12 条行为的示意数据。接到 `catalog.js` 时需要为每个 `effect` 补三项：

```js
{
  organ, type,
  near, far,        // 此刻 / 长期 的强度 0-1，由文案强度人工标定
  back: 'hours' | 'days' | 'weeks' | 'months' | 'years' | 'never',
  layer: 'A' | 'B' | 'C' | 'D'   // 证据等级，对应 UI-SPEC 的分级
}
```

`back` 是新增的核心字段，必须逐条人工判定，不可由代码推导。`layer` 用于后续在界面上标注证据强弱。
