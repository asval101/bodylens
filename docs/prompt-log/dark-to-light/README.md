## 2. AI 首轮输出与具体问题

### 2.1 第一轮：我先把原因判断错了

用户说的是「深色压抑」，我的回复开头是：

> 我不反对你的感受，但我对原因的判断和你不太一样

我给出的分析是：压抑来自**近黑 + 冷青 + 高对比**三者叠加，而不是深色本身；因此第三步「改浅色」不是唯一解法。同时给出一张三版对比（A 现状 / C 暖深 / B 浅色）和一张时间账：

- 选 C：改一个 `:root` + 十几个覆盖，2 小时推完全站
- 选 B：2 天，而且截图和视频全部要重拍

**这段的判断是错的。** 用户没有接受「先上暖深」，而是直接问「抛开时间和别的因素，哪个色调更合适」——这一问把讨论从「省不省事」拉回到「产品该是什么样」。我这才给出五条论证，结论是浅底。

这一处值得记：**我一开始把「成本」当成了决策变量，而用户要的是「正确」，成本只是执行约束。**

### 2.2 改错文件，白干半小时

在改人体配色之前，我改的是 `artwork/anatomy-base.js`，改完截图页面毫无变化。查过引用才发现：

> 那个文件没有任何地方引用，是早期废弃的草稿。真正在跑的是根目录的 `anatomy.js`

教训：**改之前先确认文件在被谁引用**，不能按文件名猜。

### 2.3 三版配色全被否，因为「心脏不能没有红」

我最初想把器官都改成青绿，出了三版：

| 方案 | 结果 |
| --- | --- |
| 青绿同族 | 心脏变深青，看起来像病变 |
| 铜色单色 | 像铜版画挺好看，但心脏变褐，像标本 |
| 灰阶 | 肺、肝、肠糊成一团，分不出来 |

共同问题是：**心脏没了红色就是语义错，不是审美问题**。最后真正要做的只有一件事——压外壳，器官一个色值都不动，代码改动 5 行。

## 3. 人工纠偏的 Prompt 与取舍

### 3.1 「抛开时间和别的因素」

这句是整条链的分水岭。它要求我在**不受工期约束**的前提下给出独立判断，而不是给一个「性价比最高」的方案。

我给出的五条论证（摘要）：

1. 内容本身已经是负面的，界面得对冲，不能叠加——记录健康的工具一旦让人不想打开就失去了作用
2. 使用场景是「随手记一下」不是「沉浸观看」——深色的护眼优势用不上，日光下对比弱的劣势全用上
3. 这一屏要读的是数字，不是氛围——血压计、体检报告为什么几乎都是浅底，这是阅读效率问题
4. 颜色要有职责，不能只营造氛围——克制的用色本身就是可信度
5. 心理联想很具体——深色像屏幕、监控、夜晚；浅色像纸、诊室、白天

同时我主动写了反对意见：

> 深色在截图和视频里更抓眼球，对比强、氛围足，放在作品集或演示里更「出片」

结论写成一句话：**深色更适合被展示，浅色更适合被使用**。

### 3.2 「不能为了省事就不了了之」

用户没有接受「先上暖深再说」，理由不是偏好，而是**这是参赛作品**。这一句同时否掉了我的时间账和我的折中方案，并加了两条额外约束：

- 「之前有什么不合适的就修改，不和用就删」
- 「别堆屎山代码，以赛事规则为准」

这直接决定了后面翻色的做法——不是一层层覆盖，而是整体按明度翻转。

## 4. 执行过程中的两个坑

### 4.1 `.panel` 改了完全不生效

卡片一直是灰的。原因是 V2 视觉层里还有第二条 `.panel` 规则，用 `--vfx-glass` 变量接管背景，而那个变量的原值是 `#deddd9→#eee` 的浅灰渐变，比米白底还暗。

**改 `.panel` 是白改，只能改变量。**

### 4.2 转换器不幂等，跑第二遍整站静默翻回深色

第一遍转完写回 `styles.css`；第二次再跑时输入已经是浅色版，于是又翻回深色——**不报错**，只是颜色全乱（搜索框从 `#0a1517` 转两次变成 `#282825`）。

是从 git 恢复原始版本重转才修好的。现在转换器入口加了保护：检测到已是浅色版就直接退出。

## 5. 一次自我证伪

16:58 那轮，我上一轮报的「移动端 390px 横向溢出」被自己推翻了：

> 无头浏览器 `--window-size=390` 时，真实视口只有 375（扣掉 15px 滚动条），但截图文件还是 390 宽，右边 15px 被裁掉，看起来就像内容溢出。

用 DevTools 协议实测：`scrollWidth = clientWidth = 375`，一个越界元素都没有。

真正改的是探索页人体——查像素才发现根因是**人和底同明度、描边不到半个像素**：

| 改什么 | 原来 | 现在 |
| --- | --- | --- |
| 描边 | `#9ca387 / 28% / 0.8` | `#8d9787 / 46% / 1.15` |
| 外壳明度 | 0.84~0.92 | 0.78~0.86 |
| 舞台 | 白底 + 灰雾 | `#f5f3ed→#e4e1d8` 柔和光背 |
| 锚影 | 0.372 散影 | 0.15 + 收紧 |

## 6. 最终结果

- 配色：米白底 `#f7f6f2` + 墨绿字 `#16211d` + 松绿 `#2a765e` + 陶土橙 `#a04a24`
- diff 只有 131 行增、108 行删，**没有新增文件**——因为先数过：`styles.css` 232 个色值里 223 个只出现一次，没有共同语义可以收敛，所以按明度整体翻转，只在非改不可的 5 处定点修正
- 80 项测试全过，线上 md5 与本地一致，375px 复查五个页面排版正常

## 7. 一句话复盘

**「浅色」不是审美结论，是使用场景推出来的结论。** 而它真正难的地方不在改颜色，在于浅色什么都藏不住——一根分隔线重了、字号差 1px 都看得见，深色里靠发光和光晕糊过去的问题会全部暴露。

## 8. 尚未解决

- 深色在截图和视频里确实更抓眼。用户现在的处理是保留浅色作为产品本体，展示时另作考虑，这与产品决策不冲突。
