过程中发现两件事

第一件：我最初改错了文件。​ 一开始我改的是 artwork/anatomy-base.js，改完截图发现页面毫无变化。查过引用之后才发现，那个文件没有任何地方引用，是早期废弃的草稿。真正在跑的是根目录的 anatomy.js，它有 96 个色值，皮肤渐变还比草稿精细。等重新按正确的文件改完，半个多小时已经过去了。

第二件：一开始想到的方向是错的。​ 我本来想“把器官都改成青绿”，做出三版给你看后，全都被否定了：

方案	结果

铜色单色	像铜版画挺好看，但心脏变褐，像标本

最后真正要做的事

真正的问题其实只有一处：一整片亮肉黄的皮肤抢了器官的戏；至于“肉色”本身，倒不是问题。所以只压外壳，器官全部保留。

皮肤、肌肉、体腔 → 明度 54%、色相 180、饱和 13%，退进深青底
肺、心、肝、胃、肾、肠 → 一个色值都没动
结果：外壳退下去以后，肺的血管纹理和红心脏反而更突出

代码改动只有 5 行（三组渐变的色值）。

下载到本地
过程消息

我的答案是：浅底，暖一点的浅底，配一个沉的绿。​

下面这条论证并非为了兼顾你的偏好，我逐条说。

为什么是浅

1. 内容本身已经是负面的，界面得对冲，不能叠加。​
这个产品讲的是“今天从你这拿走了多少时间”“哪些器官在受累”“身体年龄比实际大了几岁”。内容情绪本身就很重。深色加冷青是同一方向的加重——两个负面叠在一起，用户不想打开；而记录健康的工具，一旦让人不想打开，就失去了作用。

2. 使用场景是“随手记一下”，不是“沉浸观看”。​
课间、饭后、睡前，掏手机点两下。深色的优势（暗环境护眼、沉浸感）在这个场景用不上；劣势（日光下对比弱、截图和投影发灰）全用得上。而且它是要拿给别人看的；浅色在陌生设备、陌生亮度下更稳。

3. 这一屏要读的是数字，不是氛围。​
时间损耗、器官、趋势，全是数字。深底上的数字必须靠发光和高对比才读得清，浅底上深色文字天然清楚。血压计、体检报告、记步 App 为什么几乎都是浅底？这不是审美问题，而是阅读效率问题。

4. 颜色要有职责，不能只营造氛围。​
现在这套配色里，亮薄荷和暗面板主要在“造气氛”。浅底方案里颜色只做三件事：主色标记能点的东西、陶土橙标记不利的、其余全让给黑白灰。克制的用色本身就是可信度——健康内容一旦花哨，严肃性就掉了。

5. 心理联想的差别很具体。​
深色加冷青，容易让人想到屏幕、监控、夜晚、科技产品。浅色加绿，则像纸、诊室、白天、日常。这个作品想说的是“看见行为的回响”，像陪伴式提醒，而不像监控。

但深色也有它对的地方

深色在截图和视频里更抢眼，对比强、氛围足，放在作品集或演示里更“出片”。如果这个东西主要是“被看”，深色确实有优势。这也是它一路能走到现在的真实原因。

所以更准确的说法是：深色更适合被展示，浅色更适合被使用。​你的直觉其实是站在“使用”这一侧的。

但轻浅不等于纯白

纯白 #fff 铺满屏幕会刺眼，像 Word 文档；纯灰又像后台管理系统。对的方向是带一点暖的米白 + 一个沉的墨绿：

底用 #FAF8F3，米白，有纸的温度
字用 #1E2A26，墨绿偏黑，不用纯黑 #000（纯黑在浅底上过硬）
主色 #2C7A63，松绿，浅底上必须压深才读得清——原来那个亮薄荷 #9cdec9 在浅底上是看不见的，这是翻浅色最容易踩的坑
强调 #C46A3D，陶土橙，只给“不利影响”
最后一个诚实的提醒

浅色不比深色省事，反而更难。深色可以靠发光、暗角、模糊光晕掩盖排版和间距的问题；浅色什么都藏不住，一根分隔线重了、字号差 1px 都看得见。

所以真正的成本不在改颜色，在于改完之后得重新抠细节。这也是我上一条建议“先上暖深”的真实原因——它是给浅色争取时间，并非在躲懒。

如果你决定就是浅色，那我们直接做，按上面这套色板走。

做了什么

配色按你说的方案：米白底 #f7f6f2 + 墨绿字 #16211d + 松绿主色 #2a765e + 陶土橙 #a04a24（只给“不利影响”）。

关键是没有采用“一层层覆盖”的做法。我先数了 styles.css：232 个色值里 223 个只出现一次，它们都是十几轮手工调出来的专属颜色，没有共同语义可以收敛。所以按明度整体翻转，只在非改不可的 5 处定点修正（底色、卡片、阴影、背景光斑、剪影）。diff 只有 131 行增、108 行删，没有增加新文件。

人体单独一套：外壳压成浅灰退成“白瓷模型”，器官压到中间调但保留色相——浅底上器官就是靠颜色区分的，全调灰会认不出肺和肠。

过程中遇到两个问题，值得你知道

第一个：卡片一开始始终是灰的，我改 .panel 完全没有生效。​
原因是 V2 视觉层里还有第二条 .panel 规则，用 --vfx-glass 变量接管背景，而那个变量的原值是 #deddd9→#eee 的浅灰渐变——比米白底还暗。改 .panel 没有生效，只能改变量。改完后卡片才是纯白（采样 255,255,255 确认）。

第二个更危险：转换器不幂等，我把它跑了第二遍。​
第一遍转完写回 styles.css，第二次再跑时输入已经是浅色版，于是又翻回深色——不报错，只是整站颜色静默地全乱了（搜索框从 #0a1517 转两次变成 #282825）。是从 git 恢复原始版本重转才修好的。现在转换器入口加了保护，检测到是浅色版就直接退出。

这两个都记进项目笔记了。

先纠正一件事：移动端没有溢出

我上一轮说“移动端 390px 横向溢出，右边被切掉”——这个判断是错的。

原因：无头浏览器 --window-size=390 时，真实视口只有 375（扣掉 15px 滚动条），但截图文件还是 390 宽，右边 15px 被裁掉，看起来就像内容溢出。

我用 DevTools 协议在页面里实测：scrollWidth = clientWidth = 375，一个越界元素都没有。320px 下那 15px 来自 body{min-width:320px} 加桌面滚动条，真机（覆盖式滚动条）不会触发。所以这块不用改。

真正改的是探索页人体

我先按“舞台压深 + 接地阴影 + 暗角”做了两版，跟原版几乎看不出差别——说明我方向判错了。查像素才找到根因：

人体外壳亮度约 0.83，舞台约 0.90，只差 5%，边界根本读不出来
描边是 #9ca387 / 28% 透明度 / 0.8 宽，在 0.65 缩放下不到半个像素，等于没有描边

所以“器官漂在白雾里”，真正缺的是一条边界。三处改动：

改什么	原来	现在
描边	#9ca387 / 28% / 0.8	#8d9787 / 46% / 1.15
外壳明度	0.84~0.92	0.78~0.86（×0.955）
舞台	白底 + 一点灰雾	#f5f3ed→#e4e1d8 柔和光背
锚影	0.372 散影	0.15 + 收紧

中间试过两档：只加强描边不压深——还是散；压 7.5%——脸变成灰面具，开始跟器官抢注意力。

记下来的一条经验：深色版靠明暗自然分层，浅色版一旦人和底同明度，缺的就是那条边界——先补边界，再谈体积。浅色主题里“浅”不是安全值。
