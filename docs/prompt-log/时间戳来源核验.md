# 时间戳来源核验

三条 Prompt 链归档图里出现的时间戳，**是分享页本身的数据，不是归档时添加的**。
这份文件记录核验过程，可自行复现。

## 为什么需要这份核验

分享页的时间戳默认只在鼠标移到消息上时才显示。归档时要看到它，有两条路：

1. 给每条消息都悬停一次再截图——一次只能出一行，全页不现实
2. 注入一条 CSS 把隐藏的工具栏展开——一次全出，但**看起来像改过页面**

我选了第 2 条，因为它只影响可见性。但「我声称只改了可见性」这句话本身需要证据，
否则就是自说自话。下面是三条可独立复核的证据。

## 证据一：不注入任何样式，时间戳照样在文本里

用浏览器打开分享页的正文页，**不注入任何 CSS**，直接读页面文本，得到 5410 个字符，
其中包含全部五个时间戳：

```
10月21日 15:57   10月21日 16:08   10月21日 16:28   10月21日 16:36   10月21日 16:58
```

把这份文本与归档的 `dark-to-light/share-2026-10-21-raw.txt` 正文逐字比对：

| | 长度 |
| --- | --- |
| 归档 `.txt` 正文 | 5411（多一个开头的空行） |
| 不注入时的抽取 | 5410 |

**逐字比对结果：除了开头那一个换行，完全一致。** 一个字符都没多。

## 证据二：不注入样式，只把鼠标移上去，时间戳自己出现

见 [timestamp-check.png](./timestamp-check.png)。**同一页面、同一次加载、同一滚动位置，
没有任何样式改动**，唯一差别是鼠标位置：

| | 工具栏 opacity | 画面 |
| --- | --- | --- |
| A：鼠标不在消息上 | `0` | 没有时间戳 |
| B：鼠标移到同一条消息上 | `0 → 1` | `10月21日 15:57` 自己出现（旁边的小图标是复制按钮） |

两张图是连拍的，中间没有刷新页面，也没有跑任何脚本改动 DOM——只有一次
`Input.dispatchMouseEvent` 鼠标移动。

opacity 从 `0` 到 `1`，就是它平时看不见的全部原因。

## 证据三：注入的样式只做了什么

归档时注入的 CSS 只有两条：

```css
.cr-toolbar { opacity: 1 !important; }
.cr-toolbar > *:not(.cr-toolbar__time) { display: none !important; }
```

- 第一条：把「悬停才展开」这一层直接展开
- 第二条：把复制按钮隐掉，画面更干净（这一条只是**减少**显示，不会增加任何东西）

**没有写入任何文本，没有生成任何元素，没有修改任何时间值。**

## 如果你还是想用零注入的版本

可以。把鼠标逐条移上去截图，只是要一条消息截一张，一条链大概 5 张。
需要的话我可以按这个方式重出一版，工作量不大，只是图会变多。

## 复现方法

归档与核验脚本都在 `.tmpshot/`：

| 脚本 | 作用 |
| --- | --- |
| `archive-chain2.cjs <shareUrl> <outDir> <prefix>` | 注入展开样式，抽全文 + 逐段截图 |
| `verify-timestamp.cjs <shareUrl> <outDir>` | **不注入**任何样式，抽全文 + 悬停前后两张连拍 |
| `compose-hover.py <before> <after> <out>` | 把两张连拍裁成上下对照图（就是上面那张） |
| `stitch2.py <segments.json> <out.png> <share> <times>` | 拼长图，顶部加来源标注带 |

分享页地址写在每条链的 `README.md` 第 0 节，匿名可访问、无需登录。
`verify-timestamp.cjs` 只要一条命令就能自己跑一遍，不需要任何登录态：

```bash
node .tmpshot/verify-timestamp.cjs "<该链 README 第 0 节的分享链接>" .tmpshot/verify
```

它只会打印两个数字——抽到的文本长度、以及抽到的时间戳列表。你自己对一遍就行。
（脚本用本机 Edge 的无头模式，Windows 自带，不需要装浏览器或额外依赖。）
