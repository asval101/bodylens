# 接通大模型：三次失败里，两次错在输入而不是提示词

- 日期：2026-10-21
- 对应提交：本批次 `feat: 接通大模型解读`
- 验证：`npm test` 63 项通过（新增 7 项接口路径用例）；线上流式实测两次，输出稳定

## 1. 初始意图（用户原话）

> ok

承接上一轮我提的方案：用智谱 GLM-4-Flash（免费）接通 `/api/interpret`。

用户要的其实只有一件事：**让页面上那个「本地运行」的标签变成「AI 解读」**。但这件事背后有三道坎，任何一道没过，标签都会停在原地。

## 2. 第一处坑：404 伪装成「密钥无效」

服务端原来写死：

```js
fetch(AI_BASE + '/v1/chat/completions', ...)
```

`.env.example` 里默认值填的是 `https://api.deepseek.com`，拼出来正好是 `https://api.deepseek.com/v1/chat/completions`，一直没出过问题。

但智谱的 OpenAI 兼容路径是 `/api/paas/v4/chat/completions`。按同一规则会拼成：

```
https://open.bigmodel.cn/api/paas/v4/v1/chat/completions
```

这个地址不存在，返回 **404**。而 404 在界面上的表现是「AI 解读失败」，和密钥填错的症状一模一样。**如果不先查日志，会花几个小时怀疑密钥。**

处理方式不是给智谱写特例，而是把「补全路径」抽成一个纯函数，四种写法都认：

| 填什么 | 得到什么 |
|---|---|
| `https://api.deepseek.com` | `.../v1/chat/completions` |
| `https://api.siliconflow.cn/v1` | `.../v1/chat/completions` |
| `https://open.bigmodel.cn/api/paas/v4` | `.../v4/chat/completions` |
| 已经写全的地址 | 原样使用 |

抽成 `server/endpoint.cjs` 而不是塞在 `proxy.cjs` 里，是为了能被 `node:test` 直接 import——`proxy.cjs` 一被 require 就会监听端口，测不了。

## 3. 第一轮提示词：模型自己加了健康结论

密钥填好，`/api/health` 变成 `{"ai":"on"}`，流式出字正常。但内容是：

> 今天行为使健康时间减少 20 分钟，比昨天改善。**保持 7 小时睡眠有助于恢复。**

两个问题：

1. 「有助于恢复」是**输入里没有的健康结论**，模型自己加的。
2. 睡眠这条在数据层是**故意不给分钟数**的（只有五因素组合数据，没有按小时折算的口径），模型不但没说明「为什么不算」，还反过来夸了它一句。

这违反了 `AGENTS.md` 第 5 节第 1 条。**在别的产品里这只是「文案不够准」，在这个产品里它是内容红线**——整个评分核心就是「不把推测表现成已测量的损伤」。

## 4. 第二轮：加了规则，反而暴露出方向问题

我在 system 里补了硬规则（不得新增健康结论、证据等级必须原样引用），并把输出结构固定成四句。结果：

> 今天合计**少拿走** 20 分钟，**比昨天多** 20 分钟。这 20 分钟全因吸烟，**证据强度中等**。今晚可以尝试比平时早 20 分钟放下手机。

三处错：

| 症状 | 根因 |
|---|---|
| 「比昨天多 20 分钟」方向像是变差 | 输入里写的是 `变化：+20 分钟`，**正负号没有语义**，模型不知道 + 是好事 |
| 「证据强度中等」 | 输入是「方向 3 级、数值 3 级」，模型把它翻译成了主观档位 |
| 睡眠整条被吞掉 | 规则说「必须说明」，但没说「必须点名」，模型理解成了可省 |

## 5. 关键判断：这次不该继续加规则

第一反应是再补三条「不许说中等」「必须点名睡眠」。但停下来看，**三个错误里有两个的根因在输入端，不在指令端**：

- `变化：+20` 本身就是有歧义的。人看得懂是因为知道上下文，模型没有上下文。
- `方向 3 级、数值 3 级` 是个内部编码，模型无从知道该不该直说。

在输入端有歧义的情况下，规则写得再多也只是在**事后打补丁**，而且规则越长，模型越容易漏掉其中某一条。正确做法是把输入改成不需要解释的人话：

```diff
- 今日合计：-20 分钟。
- 昨天合计：-40 分钟。变化：+20 分钟。
+ 今日合计：-20 分钟（负数是净损耗，正数是净收益）。
+ 昨天合计：-40 分钟。
+ 今天比昨天：+20 分钟（损耗更少）。
```

一行 `（损耗更少）`，比三条规则管用。

## 6. 第三轮：输出稳定

同一请求连跑两次：

> 今天合计损耗 20 分钟，比昨天少损耗 20 分钟。这 20 分钟全部来自 1 支烟，方向和数值证据都是 3 级。睡眠 7 小时没有可靠折算口径，不计入。今晚可以比平时早 20 分钟放下手机。

四件事都对上了：方向正确、等级原样引用、无口径条目被点名、动作足够小。

`temperature` 从 0.6 降到 0.3。这个场景不需要创造力，需要的是**每次说同一件事**。

## 7. 留下的判断

- **模型只负责说人话，数字永远由代码算。** 这次三轮返工全部发生在「措辞」层，没有一次是数字出错——说明这条架构上的分工是站得住的。
- **提示词工程里最贵的不是写规则，是找歧义。** 三条规则不如一个括号。
- 遗留：`glm-4-flash` 有每分钟限频，演示时连点可能触发 429。前端已做静默降级（退回本地解读），但**视频里要避免连续狂点**，否则会拍到降级瞬间。
