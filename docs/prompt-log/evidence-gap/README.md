## 2. 我自己先给出的判断与前提

| 轮次 | 目标 | 结果 |

## 4. 三处需要判断、不能照抄的地方

**① 酒精的 −15 分钟有前提，直接乘数量就是错的**

Lancet 2018 给的是「每周超过 100g 纯酒精之后」的边际风险。如果用户喝一杯就扣 15 分钟，等于默认他已经在阈值之上，这与研究的成立前提矛盾。

处理：给权重表加 `weeklyCap: 12.5`，账本改为边际计算——

```
今日计入量 = max(0, 本周累计 − 12.5) − max(0, 本周此前累计 − 12.5)
```

额度内计 0，界面显示「本周额度内」而不是「−0 分钟」。

**② 屏幕时间的区间宽到不能只给一个数**

原文：每看 1 小时电视 −21.8 分钟，95% 不确定区间 **0.3–44.7**，跨两个数量级。

处理：保留点估计，但界面必须并列区间（`区间 1–134`），并写进权重表头规则第 7 条——**有 range 的条目不允许只显示点估计**。这也顺便解决了「C 级该不该给数字」的旧分歧：给数字，同时给区间，比不给更诚实。

**③ 睡眠不加数字，这不是没查到，是不该加**

JACC 2023 研究的是「五个低风险睡眠因素全部满足」与寿命的关系，不是「少睡一小时扣多少」。而且睡眠-死亡率是 U 型，睡太少和睡太多都升高风险，线性折算在方法上就是错的。

处理：维持「仅记录」。这是全表唯一主动放弃数字的一项，写进提交说明里。

## 5. 一处顺手修掉的隐患

`minutesFor('alcohol', 1)` 返回 −15，而 `summarize` 返回 0。两个函数语义不同却都能算出酒精分钟数，将来有人在界面层直接调前者就会绕过阈值。

处理：新增用例把这个差异固定下来，并在权重表头写第 6 条——带 `weeklyCap` 的条目只能经 `summarize` 使用。

## 6. 结果与界面

| 行为 | 之前 | 现在 |
|---|---|---|
| 香烟 | −20/支 | 不变 |
| 酒精 | 仅记录 | −15/标准杯（超出周额度部分） |
| 屏幕时间 | 仅记录 | −21.8/小时（附区间） |
| 睡眠不足 | 仅记录 | 仍仅记录 |

8 个行为里能算分钟数的从 1 个变成 3 个，与事前预估一致。

## 7. 一句话复盘

这一轮真正的工作量不在找数字，在**判断哪些数字不能直接用**。三条里只有一条能照抄公式，另两条都得加约束才成立——而这个约束本身比数字更能说明模型不是拼的。

### 8.3 当时说「睡眠不加数字」，后来改了

§4 ③ 写的是「睡眠维持仅记录」。那是 10-20 的判断，两天后（`346c812`，10-22）改了——但**不是因为找到了按小时折算的文献**，而是用户指出「界面只写『缺』，用户会把影响弱化」。改法是给一个带区间的推算值并写明成立条件，口径来源和取舍见 [sleep-ledger](../sleep-ledger/README.md)。

这条留在这里，是因为它比任何一条成功的判断都更能说明这个方法：**先判断能不能算，再算；判错了要能回头改，而且改的理由要说清楚。**
