- 日期：2026-10-20 ｜ 对应提交：`e25f942`

## 1. 初始意图

> 点击每一个器官都会有相应的动画……你说我的是纯静态文件，如果我要做比较炫酷的呢，进入网站就是动画，每一个按键都有交互的那种

上一轮我给了个具体建议，用户回「你先生成我看看」：

> 点一支烟 → 颗粒飞向肺 → 数字滚动

## 2. 第一轮：发现入口不对

**我先读代码，发现今日页根本没有人体图。** `anatomy.js` 里那套完整解剖在 `#page-explore`，首屏 `#page-today` 是纯文字账本。

这里有个选择：

- A：把人体从探索页搬一个过来 → 破坏首屏「只回答一个问题」的克制
- B：在首屏造一个极简版 → 需要决定「极简到什么程度」

选了 B。判断依据是：**首屏的人体不是用来看的，是用来给一个数字找落点的。** 它不需要纹理、不需要面部、不需要写实，只需要「一具身体 + 几个能被点亮的部位」。

## 3. 差点犯的错：我复制了一份坐标

第一版我新建了 `data/organs.js`，把器官名和锚点坐标抄了一遍。

写完立刻发现 `data/catalog.js` 第 18 行就有 `organs`，而且 `index.html` 一直在加载它。

**如果我留着那份副本，就会出现两套坐标。** 探索页改了锚点、首屏不改，粒子就会飞到一个空位置上——而且这种错不会报错，只会「点了没反应」。

删掉，改 `today-body.js` 直接读 `window.BodyLensData.organs`。并在权重表里加了一条注释：器官关联只能从 catalog 里已登记、带来源的条目取。

## 4. 第一版的器官点等于看不见

`r=3.4` 写在 SVG 里，看起来是个正常数字。但 viewBox 是 400 宽，实际显示 142px，**缩放比 0.355**，所以半径只有 1.2 像素。

截图确认：一排白点，数不清几个。

修法：`R_BODY = 7.5`（约 2.7px），`R_HEAD = 5.2`。

顺带发现第二个问题：脑（y=55）、眼（y=83）、口腔（y=103）三个点在解剖上本来就近，用同样大的点会连成一串珠子。头部用小一号之后能分辨了。

**这条记下来的原因**：SVG 的几何单位不是像素，凭直觉写数字必然错一次。

## 5. 因果顺序：粒子在已经亮着的点上空飞过

第一版的顺序是 `add() → render() → 飞`。

`render()` 里 `renderOrganLine()` 会立刻把这一笔算进去，`mark()` 把器官点亮。等粒子 620ms 后飞到，**器官早就亮了**——粒子只是在一颗已经亮着的点上空掠过，视觉上什么都没发生。

修法：`add()` 里 `render()` 之后先 `unmark(item.organs)` 把这几个器官熄灭，粒子到达时再 `pulse()` 点亮。

这个 bug 不看动画是发现不了的，因为 DOM 状态完全正确、测试也全绿。**它是「状态对了但体验错了」的典型。**

## 6. 测试暴露了我自己的认知错误

我写了一个断言：

```js
assert.ok(org.gain.indexOf('brain') !== -1, '大脑只被快走影响，应留在收益侧');
```

失败了。原因：**烟也影响大脑**。`catalog.js` 第 37 行写着「尼古丁会形成依赖，吸烟也增加卒中风险」。

我凭印象写了断言，而印象是错的。

改成两个更精确的用例：

- 烟 + 快走（器官完全重叠）→ `gain` 必须为空
- 屏幕时间 + 快走（只有心脏重叠）→ `gain` 里必须有大脑

第二个用例才真正验证了「部分重叠时只吞掉重叠的那一个」，第一个只验证了「全重叠时全吞」。原来那条断言两个都没测到。

## 7. 一个我没能验证的东西

想截动画中间帧，试了 `--virtual-time-budget=250/400/620`。三张都截在动画早期：粒子还停在起点附近，数字区是空的。

两个原因叠在一起：

1. 入场动画 `figure-in` 是 820ms，400ms 时数字透明度只有三成，截图里看不见
2. headless 的 virtual time 不驱动 `requestAnimationFrame`，只有需要重绘时才触发

**结论：截图能验证静态状态，验证不了时序。** 时序只能靠代码审查和真人手感。

这一点如实写在记录里，而不是假装验证过了。

## 8. 一句话复盘

这条链的价值不在粒子，在**「到达才亮」这个顺序**。反过来做，同样的元素、同样的时长，就只是特效；按这个顺序，它回答的是「我刚点的那一下去哪了」。
